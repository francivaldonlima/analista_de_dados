🎯 Objetivo do Projeto

Problema: Quando a UTR-221 (estação de bombeamento) perde a comunicação com o sistema SCADA, os operadores ficam sem informação sobre a pressão da rede por períodos que podem chegar a horas.
Solução: Um modelo de Machine Learning treinado com dados históricos dos sensores é capaz de prever a pressão minuto a minuto mesmo sem sinal, usando como base as últimas leituras conhecidas e o estado das bombas.

📥 Entrada
Estado das bombas, nível UTR-220,
histórico de pressão (60 min)
📤 Saída
Pressão prevista (BAR) minuto
a minuto por até 7 horas

Problema: dados brutos do SCADA têm falhas de comunicação, lacunas temporais e timestamps irregulares.

Etapas do tratamento:

1
Parse de Timestamp
Converte "01/02/26 00:00:27,954000000" → datetime
2
Mascaramento QUALITY=0
Dado inválido → NaN (não simplesmente zero)
3
Regularização 1 min
Resample para índice temporal uniforme
4
Imputação
Analógicos → interpolação linear (limite: 30 min)

🤖 Algoritmo — Random Forest Regressor

O que é Random Forest?

É um conjunto (ensemble) de várias árvores de decisão. Cada árvore aprende com uma amostra diferente dos dados. A previsão final é a média das previsões de todas as árvores.

Isso reduz o overfitting e aumenta a robustez.
Por que foi escolhido?
  • Lida bem com dados não-lineares
  • Robusto a outliers
  • Fornece importância das features
  • Não precisa de normalização
  • Rápido para prever (tempo real)
Configuração do modelo: 
RandomForestRegressor(
    n_estimators = 200,  # 200 árvores
    random_state = 42,   # reprodutibilidade
    n_jobs       = -1    # todos os núcleos CPU
)
Divisão dos dados:
80% treino (dados mais antigos)
20% teste (dados mais recentes)

⚠️ Sem shuffle! Série temporal deve manter a ordem cronológica.

⚙️ Lógica de Controle das Bombas

Pressão ≥ 1,68 BAR  →  Bombas DESLIGAM    |    Pressão ≤ 1,55 BAR  →  Bombas LIGAM

Por que isso é importante?

As bombas operam em rodízio exclusivo: B1 e B2 nunca funcionam ao mesmo tempo. O controle por setpoints simula o comportamento real do sistema de automação durante a falha.

Sem essa lógica, a previsão teria pressão continuamente subindo ou caindo.
Como funciona no modelo: 
if pressao >= 1.68:
    bomba1 = 0  # desliga
    bomba2 = 0
elif pressao <= 1.55:
    bomba1 = 1  # liga
    bomba2 = 1
Esses valores são ajustáveis no dashboard

🧠 Conceitos de Machine Learning Utilizados

Série Temporal Supervisionada
O problema é transformado em aprendizado supervisionado: usamos leituras passadas (t-1, t-5, t-15, t-60) para prever a leitura futura (t+1).
Feature Engineering
Criação de variáveis derivadas: lags, médias móveis, tendências, indicadores de rodízio. Cada variável captura um aspecto diferente do comportamento.
Walk-Forward Validation
Divisão temporal (80% treino / 20% teste) sem embaralhamento, respeitando a ordem natural dos dados.
Previsão Recursiva
Para prever múltiplos passos à frente, a previsão de cada minuto é usada como entrada do próximo. Isso permite simular horas de falha com apenas um modelo de 1 minuto.
Imputação de Dados
Interpolação linear para sensores analógicos: estima valores entre dois pontos válidos. Forward-fill para status binários: mantém o último estado conhecido.
Importância de Features
O Random Forest calcula quanto cada variável contribuiu para as decisões das árvores. Permite entender quais dados são mais relevantes.

🔬 Arquivo de Validação — UTR221_ML_validacao.py

Este script é o laboratório científico do projeto. Ele treina o modelo, compara horizontes diferentes e gera previsão futura de 7 horas.
O que ele faz:
  • Treina modelo 1 min e 30 min simultaneamente
  • Compara importância das features lado a lado
  • Calcula MAE, RMSE, R², MAPE, Acurácia
  • Previsão recursiva das próximas 7 horas
  • Exporta DF6_futuro_7h.xlsx
  • Gera gráfico previsao_futura_7h.png
  • Gera gráfico coeficientes_comparativo.png
Por que dois horizontes?

No horizonte de 1 minuto, a pressão atual (lag1) domina com 99% de importância — previsão trivial mas muito precisa.

No horizonte de 30 minutos, o rodízio das bombas ganha 9× mais importância, revelando a física real do sistema.

O modelo de 1 min é usado no dashboard por sua maior precisão na simulação recursiva.
